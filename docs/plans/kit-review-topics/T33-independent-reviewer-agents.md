# T33 — Independent reviewer agents: UAT persona driver, data-integrity verifier, UX evaluator

**Category:** Gap + Module (new capability) · **Status:** **Decided (2026-07-28)** — grilled · **Issue:** epic #145 (sub-issues #146–#151) · **Related:** T31 (parked these two agent types; T31.6 author-independent criteria, T31.7 adversarial gate, T31.8 verdict/advisory classes, T31.11 retry-vs-defer), T34 (UX design mode — split out, same agent identity), T35 (encoding policy — split out), T17 (feature-spec v2 — this is a consumer; supplies requirements to it), T28 (UAT's two audiences — this is the third: independent verification), T5 (failure-driven diagnostics + evidence bundles), T3 (module tiering), T23.2 (manifest allowlist), T2/T32 (portable-shell / runtime — supplies requirements to)

**Problem / Origin:** In **ShelterSync**, a change sentence-cased lookup options. The
implementation worked, the UI looked correct, and nothing appeared wrong — until Chris
opened an unrelated **animal edit form** days later, for an unrelated reason, and could
not save: the backend was still matching lowercase. A break in an *untouched* flow,
caused by a change to a *shared vocabulary*, sat undetected because a solo developer has
no QA analyst to walk scripts after every change.

Every verification surface the kit ships is **run by the agent that did the work, scoped
to the work it just did** (`TESTING_STANDARD.md`; `/qa` diffs `git diff --name-only`;
`UAT_SOURCE_OF_TRUTH.md` per work item; `coding.md` Impact Analysis is a checkbox the
implementer ticks about its own change). Nothing drives the running app, nothing is
scoped to flows the diff didn't touch, nothing is independent of the author. The kit
ships zero `.claude/agents/` today. `UI_STANDARD.md` §9.2 — itself a ShelterSync
port-back — would have *prevented* this incident and could not have *detected* it;
prevention rules accumulate one incident at a time, detection is the missing capability.

Grilled 2026-07-24 → 2026-07-28 (16 exchanges). Two real-world corpora fed the grill: a
ShelterSync demo bug list (16 items — used to validate the roster; #11 cancel-saves and
#17 tier-mismatch are the verifier's crown jewels, #6 dead-end back button the driver's,
#13 raw-UUID and #9 can't-see-calculated-risk the UX-conformance agent's, and #2/#3/#4
correctly caught by *nobody* — missing features are out of scope), and the SPEC-ADOPT-000…006
set (used to pressure-test the spec-as-reviewer-input relationship → routed to T17).

## Settled going in (grill inputs)

| # | Choice | Consequence |
|---|---|---|
| A | Three agents: UAT persona driver (verdict), data-integrity verifier (verdict), UX evaluator (advisory) | Persistence is verified independently of the UI that claims it saved |
| B | Ratchet runner: exploratory persona drive → confirmed flows codified into committed specs | Discovery stays naïve; re-runs get cheap and deterministic |
| C | Durable journey registry derived from spec Journey layers + `docs/PERSONAS.md`, criticality per flow | Tiered runs: touched-by-diff / critical-only / full |
| D | Reviewers run locally, on demand, strongly suggested after large changes | No CI/cloud-agent minutes |

## Decision (Chris, 2026-07-28 — grilled, "approved")

- **T33.1 — Roster of three; invariance is a property of the *agent*, not a kit-wide rule.** Whether an agent's authority is *verdict* or *advisory* follows from whether its findings are objectively falsifiable. A **QA/UAT driver** and a **data-integrity verifier** must be invariant (falsifiable → verdict). A **UX evaluator** is more subjective (→ advisory). This gives T31.8's verdict/advisory split a *reason* rather than an assertion.

- **T33.2 — The verifier is paired, log-not-verdict, and storage-independent.** It consumes the driver's structured **action log** ("selected the option labeled `Spayed/neutered` on animal 41") — never the driver's pass/fail — and asserts *intent vs storage* through a channel the UI cannot influence (API read / DB query). It catches the dangerous variant of the incident where the UI shows a green toast over a value the backend can't match. No standalone verifier runs (it needs a persona to have done something). Degrades API-read → `BLOCKED`; it **never** falls back to trusting the UI, because that erases its only reason to exist.

- **T33.3 — Invariants: a criteria-independent failure source.** The incident violated no acceptance criterion — a pure judge-against-pre-authored-criteria agent walks past it. The kit ships a fixed **universal invariant set**, checked on every walked flow regardless of any document: *round-trip* (every mutation survives a fresh read, not the optimistic UI), *offered-means-accepted* (every option a control offers can be saved ← the incident, stated generally), *no-silent-failure* (no unhandled 4xx/5xx or console error on a happy path), *no-dead-end*. An invariant failure outranks passing criteria (a criterion can be wrong; a broken save cannot be right); waiving one is an ADR, not a checkbox. Each invariant must name its evidence artifact or it isn't an invariant. *Offered-means-accepted* runs cheap always (the option the persona would pick), exhaustive when the diff touches a shared vocabulary. **Feature-specific** invariants (e.g. SPEC-ADOPT NFR-1 org-isolation) are *declared in the spec* — a requirement supplied to T17, not prescribed here.

- **T33.4 — Independence: "may read what should be TRUE, not how to DO it."** The driver may read the persona, the journey **goal**/done-condition, business rules (BR-n) and edge cases (EC-n), and the invariant set. It may **not** read the diff, the implementation conversation, the spec's numbered **steps**, the source, or the change's acceptance doc — each of which converts a naïve sweep into a spot-check aimed where the change was (T28.3's goals-not-steps reasoning, applied to an agent). Enforced by a **scoper/driver split** (a scoper reads the diff and selects journey IDs; the driver receives IDs and never learns why), plus tool restriction — a *partial* firewall with a stated limit (a subagent with `Read` could cat a diff; the guarantee is only that it's neither handed one nor given a git tool or reason to seek one). The driver never knows it's re-checking after a change. Corollary: the driver's brief and a beta guide (`BETA_GUIDE_TEMPLATE.md`) are the same artifact.

- **T33.5 — Registry: durable, discovered by journey not by outcome.** A markdown registry (`JRN-<DOMAIN>-NNN`, mirroring T24.3) derived from spec Journey layers + `PERSONAS.md`. Discovery (a driver mode) may harvest **journeys** — that a flow exists, its persona, its starting point — but **never outcomes**: observed behavior never becomes an assertion, or discovery would canonize the very bug you haven't found yet. Entries carry `discovered`/`authored` × `unverified`/`verified`; an **unverified entry still runs invariants**, so a freshly discovered registry catches the incident class on **day one** with no spec written. Discovery *proposes*; a human *merges* (offer-never-apply). Two human-owned criticality tiers (`critical`/`standard`; criticality is a product judgment → advisory-class, agent may propose). An **entities/vocabularies-touched** column drives blast-radius scoping. Keep-current per T30.2; coverage backlog is read directly from the columns (blank codified-spec ref, `unverified` rows).

- **T33.6 — UX evaluator = standards-conformance for the running UI, with a notes-margin; never proposes features.** Its checklist *is* the project's UX standard applied to the live app (`DOCUMENTATION_STANDARD.md` audience-first/no-internal-leakage/error-copy; `UI_STANDARD.md` §3.1 how-do-I-know, §9.1 sentence case, §9.2 humanized codes, loading/empty/error states). Every finding **cites the clause it violates** — so even the advisory agent is falsifiable in its *basis*, advisory only in its *authority*. It **never proposes features**: absence of a capability is out of scope by construction (→ roadmap intake), so #2/#3/#4-style items stay silent. Genuine friction that violates no clause becomes a **note** (human-triaged, never auto-filed); a *recurring* note is evidence of a missing clause → `/evergreen` standards-drift lens → the **notes-to-clause feedback loop**. The enforcement target is a three-part stack: best-practice base (the generic `UI_STANDARD.md`, already adaptable) + interview-derived clauses + decomposed design intent.

- **T33.7 — Driver-seam architecture; the driver is a per-surface pluggable capability, not a fixed tool.** The reviewer's judgment is tool-agnostic (walk this journey as this persona, act, assert round-trip, cite evidence). *How* actions reach the app is a **driver** behind a small contract (navigate / act / snapshot / read-back / emit-evidence) with a capability flag: **interactive** (agent steers live → discovery + full ratchet) vs **playback-only** (scripted regression only). The kit ships the contract + paved-road *names* per surface and **mandates none** — settling "Playwright MCP vs Bash" (neither; there's a seam) and "is requiring an MCP acceptable" (no hard dependency on any MCP).

- **T33.8 — Native mobile is in v1 scope; the native driver is an interactive+playback *pair*, selected by a spike.** ShelterSync ships a **Flutter** native app with no responsive-web equivalent, and much of the demo bug list is mobile — so web-only would miss a third of the real bugs. Maestro (the speculative paved-road entry) is re-scoped by first contact as a *playback* candidate only; it can't be explored through. The native driver is therefore a pair — interactive (semantics-tree/accessibility MCP or Appium) for discovery + naïve drive, playback (Patrol / Maestro) for codified regression — chosen by a **selection spike** driving real example bugs (#6, #11, #14), which **revises `PAVED_ROAD.md`'s mobile row via ADR** on evidence rather than leaving the guess standing. Flutter note: an agent-drivable semantics tree is the *same work* as screen-reader accessibility (`UI_STANDARD.md` §7) — the spike checks whether ShelterSync's tree is rich enough or the driver falls back to vision-and-coordinates.

- **T33.9 — Ratchet: reviewer emits a *proposal*; a coding step lands it.** A confirmed flow's output is a **structured spec proposal** (persona, journey, actions-as-executed with real element identifiers, assertions, evidence) — *data, not committed code*. Landing it as an executable test (Playwright/Patrol/…) is an ordinary coding task under `coding.md` + PR review. This keeps the reviewer read-only and keeps the *judge* from authoring its own future regression (a subtly wrong self-authored assertion would become a permanent green lie). Payoff: **pay agent-tokens once to discover/codify a flow; regression is deterministic test code that costs zero agent-tokens forever after** — which is why the reviewer stays local (its costly naïve pass runs once) while the codified specs are just normal E2E tests the project may run in CI (no contradiction). Spec maintenance = normal test-fix; *journey* drift = `/evergreen` + registry keep-current.

- **T33.10 — Trigger: "large" = *touched a shared surface*, not diff size.** The incident was one line; any size metric waves it through. The trigger is the Impact-Analysis categories (`coding.md`): enum/**lookup vocabulary**, DB column/constraint, seed/default, shared type/helper, plus a present migration. The suggested run's default tier for such a change is **blast-radius** — journeys that *read/write the changed shared surface even if their own files didn't change* (the untouched-animal-edit-form catch), computed from the registry's entities-touched column + spec Data-touchpoints. Tiers: touched-by-diff / blast-radius / critical-only / full. The suggestion lives as a `/preflight` rung + a `coding.md` Impact-Analysis line (detection paired with the existing prevention sweep); **offer-never-apply** — it names the risk and hands over the command, never auto-runs. Only as good as the registry's touchpoints are populated (undeclared journeys still run invariants but can't be blast-radius-targeted).

- **T33.11 — Findings exit by authority class; verdict auto-files.** Verdict (driver/verifier, falsifiable + cited evidence) → **auto-filed** as a bug issue. Advisory (clause-cited) → **drafted** for human promotion (T31.8: advice must not launder itself into work). Note → report section, **never filed**. One per-project knob downgrades verdict→draft for teams wanting a triage gate. Filing is non-destructive, so this autonomy axis is **separate from and far lower-stakes than** T31.2's code-execution ceiling. Guards: de-dup keyed on (journey + invariant + surface); one human-readable batch summary per run. Verdict tagging is forward input to T31's delivery gate.

- **T33.12 — Safety: never production.** The reviewer *mutates* (creates/edits/cancels), so it **refuses to start** unless config asserts a non-prod target (`{{REVIEW_BASE_URL}}`/review-store marker) and aborts on a prod-like host. v1 = **config-assertion + loud refuse-to-run**, mitigated by the run being human-invoked and present; a *hard interlock* is deferred to T32 (enforcement that can't depend on model judgment). A seeded, **resettable** instance is required as a contract (`{{DEV_COMMAND}}`-shaped), not shipped; the reviewer never auto-resets and reports `dirty state`. Reuses `TESTING_STANDARD.md`'s Data Realism Review. The round-trip invariant needs **no pre-seeded expected value** (self-referential: what the driver entered is what must persist), so seed data need only be rich enough to reach the forms.

- **T33.13 — Evidence and retry.** **No evidence, no verdict** — every verdict cites a snapshot, a network response, or a storage read; an uncited "save worked" is a note, not a verdict (the guard against a reviewer that claims it clicked save and didn't). Retry keys on T31.11's objective line: the *check didn't run* (driver crashed, environment down, MCP hung) → **retry once fresh, else `BLOCKED`**; the *check ran and found a failure* → that's a **finding, filed, never retried away**.

- **T33.14 — Packaging: a new `review` module and the kit's first shipped agents.** Not core (needs a driveable UI + live environment + journeys — like `ui`/`reports`). Trigger: "driveable UI + want independent verification." Owns the reviewers, commands, driver contract, standard, and registry. Ships the kit's **first `.claude/agents/`** — three definitions with restricted tool sets (partial independence enforcement, stated limit). **Gap surfaced:** `scaffold-module.sh` only copies files and cannot merge into an existing `.claude/settings.json` — so v1 ships a documented permissions fragment merged by hand, and **config-merge is logged as a concrete T32 requirement** (the second feature after T31 to hit the tooling seam). Encoding (applying T35's principle in miniature): **markdown** for human-curated/prose (standard, agent defs, briefs, registry — revisit registry encoding if scale/pipe-escaping bites), **JSONL/JSON** for machine records (run journal, de-dup keys — forward-compatible with T31's run-journal), native artifacts for evidence.

- **T33.15 — Sequencing: T33 is NOT blocked on T32, and supplies requirements to T31/T32.** It needs judgment surfaces (standards + agent defs) + paved-road driving, no enforcement primitives — so unlike T31 it proceeds now. It inverts the dependency: verdict/advisory tagging → input to T31's gate; config-merge + non-prod interlock → inputs to T32. **Acceptance exit criterion:** scaffold `review` into ShelterSync, restore the sentence-case lookup change, and confirm an independent run reports the save failure **without being told where to look** — a design that can't reproduce that catch hasn't solved the problem.

**Spin-offs recorded:** **T34** (UX *design mode* — guiding a non-designer to decompose vague intent into an enforceable UX standard + journeys; same agent identity as T33.6's reviewer; shared notes-to-clause loop). **T35** (encoding policy — markdown-first vs fit-for-purpose formats, kit-wide; cross-linked T32). **T17 reactivation** (spec-template v2 requirements: self-containment doctrine, feature-invariant *declaration* form, UX/tone clause separation, notation freedom, BR-authoring guidance — with the conceptual→physical binding staying a T33 review-time artifact, **not** a spec slot). **Native-driver spike + PAVED_ROAD revision** (a T33 sub-issue). **BR-authoring guidance** → folded into T17.
